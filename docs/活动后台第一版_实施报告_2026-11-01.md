## 上线前需要负责人完成或确认的步骤

完整顺序与恢复办法见 [上线与恢复操作单](./operations/events-admin-launch-runbook.md)。以下均为待执行，不代表已上线。

1. 恢复 Wrangler 授权，只读核对 `cmi.community` 当前 Worker、D1/R2 绑定、Time Travel 保留期；保存当前版本、bookmark、完整 SQL、媒体哈希及权限。不要把凭据写入聊天或 Git。
2. 准备 staging 与 production 各自的私有活动桶、独立备份桶；确认没有公开域名或 `r2.dev` 绕过。配置唯一管理员邮箱、Resend 发件能力、认证 Secret 与随机 `INTEGRATION_KEY_EPOCH`，实际验证邮件及 OTP 限制。
3. 先在 staging 迁移和演练。生产 remote migration 命令仅写在下面，**本次没有执行**：

   ```sh
   npx wrangler d1 migrations list DB --remote --env production
   npx wrangler d1 migrations apply DB --remote --env production
   ```

4. 将 10 场真实海报复制进私有桶，逐对象回读核对 SHA-256、字节数、类型和尺寸，再将对应媒体标为 ready。迁移默认 pending；只执行 SQL 就切换网站会隐藏这些活动。禁止将本地 `test:seed:events` 合成图用于生产。
5. 先私下归档受管活动的旧公开原图、缩略图、版本和别名，再按批准清单撤除公开入口并清缓存；核对旧资产域名、历史 Worker 路由和所有绕过入口。180 张历史海报不在撤除范围。旧副本或缓存未处理前，不能承诺下架后所有新请求都不可访问；已经被下载的副本无法撤回。
6. 从未激活的 `wrangler.events-backup.example.jsonc` 建立独立备份配置，核对实际 ID、版本及 Secret；先手动验证，再启用清迈每日 04:00 任务、失败与超过 24 小时无成功备份告警。落实 35 日／12 月保留、每月加密离线副本和隔离恢复演练。SQL 导出当前有 32 MiB 上限，须在首次真实演练中确认规模。
7. 恢复演练必须用新隔离 D1，核对 SQL 引用的全部媒体哈希，重放独立下架记录；恢复后清除旧会话／验证码并轮换密钥 epoch。不能把直接回滚旧 Worker 作为下架保护，它可能重新开放旧静态路径。
8. 以上完成后，由负责人明确批准上线，再安排受控发布与生产验收。本次仅交付本地分支和提交。
