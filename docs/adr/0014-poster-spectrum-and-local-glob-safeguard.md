# ADR 0014：随机、像素色谱排序与本地 glob 安全修补

- 状态：Accepted
- 日期：2026-11-18
- 关联 Issue：[#60](https://github.com/CMI-Community/Website/issues/60)
- Extends：[ADR 0013](./0013-event-museum-time-order-and-motion.md)

## 上下文

维护者明确要求新增随机排序与从实际海报提取主色／主要色彩后的色谱排序，并处理截图和依赖问题后上线。既有公共历史图片域没有 CORS 许可，直接 Canvas 读取会失败。picomatch 4.0.7 存在已公开的单分支重复 extglob ReDoS；官方 npm 尚无修复版本，导致现有审计门禁失败。

## 决策

1. 保持时间倒序与同步向上默认值。四种排序使用可直接点选、可键盘激活且包含 `aria-pressed` 的按钮。随机使用 Fisher–Yates 洗牌，每次选择或“重新打乱”生成一次种子，切换速度／方向／滚动方式时顺序稳定。
2. 按需读取每张图片实际像素，以 48×48 采样和 RGB 量化保留占比最大的主色与六个主要色彩；相近色相合并后选择有足够占比的彩色主簇排列红、橙、黄、绿、青、蓝、紫，黑白灰按明度置后，失败项最后。中性纸张可能占比最大，仍保留其真实 dominant，但用主要彩色簇决定色谱位置。结果为算法近似，不代替人工艺术判断。
3. 仅在选择色彩排序时分析，最多六个并发请求，显示进度并在本次浏览器会话缓存；完整分析后一次排序。单图错误可重试，不妨碍其他排序与详情。
4. 新增同域只读历史图片入口，只从当前已发布投影匹配公开 id，再读取白名单 R2 图片键；拒绝未发布、下架、路径穿越、外部 URL 和写方法。受管海报复用现有媒体鉴权，图片数据不发给第三方。无公开管理字段、数据库或媒体迁移。
5. 在 `vendor/picomatch-safe` 保留上游 4.0.7 MIT 源码和溯源，仅对含嵌套通配或重复符的单分支重复 extglob 复用上游 risky-pattern 字面匹配路径，并禁止通过递归选项关闭此保护。通过本地 npm override 替换全部传递副本；恶意模式使用独立进程硬超时测试，同时验证普通构建 glob。保留原 npm audit 门禁、阈值和其他公告检查，不靠忽略公告、强制降级或伪装官方修复版本放行。

## 代价与撤销条件

色彩分析首次需要下载公开海报；会话缓存减少重复工作，同域入口每次检查发布状态。中性图片、渐变与照片的主色是算法估计。四种选择直接显示会增加控制条宽度，窄屏沿用设置面板。

本地 fork 有维护成本，包名明确与官方不同，不能把 registry 审计当作该 fork 的安全证明。出现官方修复版本时复核攻击回归与构建兼容，再删除 vendor 与 override。复杂重复单分支 glob 改为字面匹配是有意限制，本项目配置不使用此语法。CI 与本地测试必须证明普通路径匹配及构建仍可用。

## 发布与回滚

沿 PR、required CI、staging、受保护 production Environment 上线；维护者本轮已经授权。当前生产 baseline 已完整留存，新候选覆盖四种排序的进度、失败、恢复和实际布局。旧未发布候选保留，不冒充其原生截图已经补拍。新版没有原生排序下拉框，按实际 UI 记录该状态不适用，并拍摄全部可见排序按钮。

回滚到 v0.5.0 代码不删除任何活动、媒体或权限数据；保留本地 fork 与失败历史的 Git 记录。
