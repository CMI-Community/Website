# ADR 0008：近期活动目录与 Event Museum 自动流转

- 状态：Superseded
- 日期：2026-08-27
- 关联 Issue：[#26](https://github.com/CMI-Community/Website/issues/26)
- Supersedes：无
- Superseded by：[ADR 0009](./0009-recent-activity-timeline.md)

## 上下文

- `VERIFIED`：官网首页由 Community Hero、Photo Museum 与 Event Museum 组成；Event Museum 当前读取版本化 R2 海报目录。
- `VERIFIED`：Projects 已使用仓库内类型化目录表达系列和期次，但菜单尚未明确标注两级层次。
- `VERIFIED`：WaytoAGI 第 27 期清迈场公众号原文公开活动日期为 2026-08-30、时间为 12:30–17:30（Asia/Bangkok），并提供公开招募海报与详情链接。
- `OBSERVED`：本期只需要少量、经审核的近期活动；当前没有运营后台、活动内容类型或公开活动写 API。
- `VERIFIED`：原始海报、授权材料和公众号抓取输出不得进入 Git；公开媒体通过版本化 R2 路径交付。

## 决策驱动因素

- 首页只应突出尚未开始的活动，并在活动开始后自动回到历史档案叙事。
- 同一条活动不应由首页、Projects 和 Event Museum 三处各自维护日期与链接。
- 时间边界必须可测试，不能依赖人工在活动当天改代码。
- 活动海报需要支持移动端横向浏览、放大、键盘操作和减少动画。
- 当前活动数量不支持为了“上传”体验提前建设后台、权限和发布工作流。

## 备选方案

### 手工切换首页与 Event Museum

- 优点：实现最少。
- 代价：活动开始时依赖人工发布，容易出现过期招募或档案遗漏。

### 立即建设 D1 活动 CMS

- 优点：运营人员可在线创建、编辑和发布活动。
- 代价：需要新增内容模型、权限、草稿、审核、媒体上传与审计，不符合本期范围和风险收益。

### 代码审核式活动目录

- 优点：日期、海报、详情链接和系列归属只有一个审核源；可在 SSR 请求时自动投影到近期区或 Event Museum。
- 代价：新增活动仍需提交代码 PR，不能由运营人员即时自助发布。

## 决策

1. 新增带类型的 `ActivityDefinition` 目录，保存公开活动 ID、标题、带时区开始/结束时间、日期文案、海报 R2 路径、详情 HTTPS 链接和系列归属。
2. SSR 在每次首页请求中使用同一个参考时刻分区：`startsAt` 晚于参考时刻的活动进入近期区，按开始时间升序且最多 5 条；已到开始时刻的活动进入 Event Museum 投影。
3. 活动海报使用 `activities/<series>/<issue>/vN/` 版本化 R2 前缀；Worker 只开放显式匹配的只读 GET/HEAD 路径，原始公众号导出不进入 Git。
4. 历史活动转换为现有公共海报白名单字段，与 R2 `poster-wall/v1` 目录按活动 ID 和详情 URL 去重合并；不修改原海报目录，也不新增公共写 API。
5. 近期活动区位于首页主标题与 Museum 入口之间，使用单行横向滚动、完整海报缩略图、标题和可选详情外链；点击海报打开可访问的同页放大层。
6. 指针设备可获得随鼠标位置变化的 3D 倾斜；键盘、触摸和 `prefers-reduced-motion` 不依赖该效果完成任务。
7. Projects 菜单继续使用单一面板，明确标注一级系列与二级期次，不新增级联菜单；原生期次同窗口，外部期次新窗口。
8. Discord 继续作为普通社区链接保留，但不再占用吸顶导航的强调按钮，也不在社区入口中使用 featured 状态。
9. 本期不建设活动 CMS。运营频率证明代码审核不足时，再以独立 T3 评估 D1 内容模型、权限、草稿和媒体上传。

## 后果

- 正面：首页不会长期展示过期招募；同一目录可以稳定驱动近期区与历史档案。
- 正面：最多 5 条、日期边界、HTTPS 和公共字段可以在发布前自动验证。
- 正面：活动媒体延续现有 Worker/R2 安全边界，不把原始海报放入 Git。
- 负面：新增活动仍需开发者或维护者提交目录和 R2 资产。
- 负面：请求时钟决定活动所在区域；错误的带时区时间会造成错误流转，因此必须在 PR 中复核。

## 迁移与回滚

1. 从公众号公开原文提取第 27 期事实与海报，在仓库外生成公开优化版本并上传 staging R2。
2. 先在本地使用活动开始前后的固定测试时钟验证两个投影，再部署 staging 做真实时间验收。
3. production 只在内容负责人明确批准后上传同一哈希媒体并部署 Worker。
4. 回滚恢复上一 Worker 版本；版本化 R2 对象保留不删，旧 Event Museum 目录不被覆盖。

## 推翻条件

- 每月活动数量、跨语言编辑或多人协作证明代码 PR 成为发布瓶颈时，以新 ADR 评估 D1 活动 CMS。
- 活动延期、取消或多时区规则无法由单一开始时刻安全表达时，扩展显式状态机并迁移目录，不在组件中加入例外判断。
