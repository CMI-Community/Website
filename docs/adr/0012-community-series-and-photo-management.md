# ADR 0012：社区系列、照片与历史活动管理

- 状态：Proposed
- 日期：2026-11-15
- 关联 Issue：[#54](https://github.com/CMI-Community/Website/issues/54)
- Extends：[ADR 0005](./0005-homepage-museums-and-public-photo-catalog.md)、[ADR 0010](./0010-managed-events-and-scoped-integrations.md)

## 上下文

VERIFIED：现有后台一次读取 D1 活动，但使用文字列表。照片从版本化 R2 目录读取，没有编辑后台。活动的 series 字段仅有名称和期数，不能配置 logo 或介绍。历史海报未纳入编辑。

## 决策

系列栏目作为独立 D1 实体，保存稳定标识、slug、名称、介绍、logo、发布状态、排序和版本。活动类别继续表示内容类型；系列表示持续开展的社区栏目。受管活动通过独立版本化关系归属一个系列，保留原活动及集成合同。

照片以 D1 为管理索引，支持说明、状态、排序、活动与系列关联。新上传使用既有管理员认证和私有事件媒体校验。公开照片和 logo 通过发布关系校验后读取，不将私有对象键投影到公开数据。

历史照片通过显式幂等导入建立索引，不复制原媒体。导入标记区分“尚未导入”和“全部照片已隐藏”，防止旧目录重新出现。历史海报采用版本化元数据覆盖层，保留原日期文字和精度，不补造起止时间；已迁入 D1 的记录继续按现有规则去重。旧记录可以在后台修改介绍、系列及官网可见性。

管理员写入需同源请求、现有唯一管理员及 OTP 验证；新管理接口不扩大机器授权范围。编辑使用 If-Match 检测并发，隐藏采用可恢复状态，不物理删除原始文件。

公开系列目录按已发布栏目组织已发布活动与照片。隐藏系列不再公开其栏目页和 logo；照片独立发布状态决定其在照片墙及公开图片代理中的可见性。

## 备选方案

- 继续修改 R2 JSON：改动较少，但缺少并发控制、关联查询和受管状态。
- 将全部旧海报转换成新活动：会强迫不完整历史资料满足新活动的精确时间要求，且增加迁移成本。
- 采用增量 D1 索引和覆盖层：保留原资料和链接，明确区分新活动和档案资料。本候选采用此方案。

## 边界

旧照片和历史海报已在公共资源域名发布。后台隐藏可以控制官网索引及受管代理，不能撤回此前下载、外部缓存或既有公共域名直链。彻底撤回旧资产需要另行迁移和缓存处理，不能声称仅修改 D1 就完成。

本记录是本地实施候选；生产数据库迁移、资料导入与发布未执行。现有活动备份不自动覆盖新增系列、照片和档案覆盖表，上线准备必须包含这些表及新增私有媒体的备份和隔离恢复验证。

## 迁移与回滚

新增表采用增量迁移，不覆盖原目录或活动数据。先在本地合成环境测试导入、重复导入、隐藏、关联及并发冲突。上线前按现有发布流程备份、演练并回读验证。回退 Worker 前检查新增发布/隐藏状态，避免旧版本忽略覆盖层而重新公开已隐藏内容；不能仅凭代码回滚声称数据状态已恢复。

## 推翻条件

如需要多栏目归属、成员级上传权限、原图彻底撤回或公开资源域名统一鉴权，另建 ADR 扩展关系及存储策略。
