# ADR 0009：近期活动使用双侧连续时间线

- 状态：Accepted
- 日期：2026-08-28
- 关联 Issue：[#29](https://github.com/CMI-Community/Website/issues/29)
- Supersedes：[ADR 0008](./0008-upcoming-activity-lifecycle.md)

## 上下文

- `VERIFIED`：活动目录已经保存带时区的 `startsAt` 与 `endsAt`，首页和 Event Museum 由同一目录投影。
- `VERIFIED`：ADR 0008 以活动开始时刻为分界，活动一开始就从首页近期区消失并进入 Event Museum。
- `OBSERVED`：该规则让用户无法在首页连续看到刚刚完成的活动，也没有表达“进行中”状态。
- `DECIDED`：近期区域需要同时承载即将、进行中和最近完成的活动，并保持一条可横向浏览的时间线。

## 决策驱动因素

- 用户需要同时预览接下来可以参加的活动和最近发生过的活动。
- 首页近期区必须保持有界，完整历史仍由 Event Museum 承担。
- 状态必须由带时区的目录时间自动计算，不依赖活动当天人工发布。
- 状态文字、键盘、触摸、减少动画和 390px 布局必须保持可用。

## 决策

1. 活动状态由同一参考时刻计算：`now < startsAt` 为 `upcoming`，`startsAt <= now < endsAt` 为 `ongoing`，`now >= endsAt` 为 `completed`。
2. 首页使用一条连续时间带：左侧先放进行中、再放即将举行；右侧放已完成；中间使用 `NOW / 现在` 分隔。两组都按距离当前时间从近到远、从左到右排列。
3. 左侧最多显示 5 场。右侧先保留所有结束未满绝对 24 小时的活动，再用较早的最近完成活动补足到 5 场；若 24 小时内完成超过 5 场，右侧可临时超过 5 场。
4. 活动在 `endsAt` 到达时立即进入右侧并显示“已完成”，同时进入 Event Museum；24 小时规则只保证首页最短保留，不延迟状态切换。
5. 三种状态都以文字标签表达，不能只依赖颜色。任一分组为空时保留紧凑空状态，不隐藏整个近期区域。
6. 海报放大、3D 指针反馈、详情新窗口、焦点恢复和减少动画继续适用于全部状态。
7. 活动目录仍是唯一审核源；不新增 D1、R2 对象、公共写 API、活动后台或取消/延期状态。

## 后果

- 正面：首页形成未来与最近历史连续可见的活动时间线，刚结束的活动不会失去入口。
- 正面：Event Museum 继续保存完整历史，首页只承担有界的近期回看。
- 负面：极端密集活动场景下，为满足 24 小时保障，右侧会短暂超过 5 张。
- 负面：取消、延期和报名截止仍无法由当前三态表达，需要未来显式扩展目录状态。

## 迁移与回滚

1. 只修改类型化投影、首页组件、样式和测试，不执行 D1 migration，也不写入 R2。
2. 先完成本地固定时钟边界测试，再部署 staging 做桌面与 390px 目视验收。
3. production 仍需内容负责人明确批准；发布目标为 `v0.3.1`。
4. 回滚恢复上一 Worker 版本；活动目录和公共媒体均无需撤销。

## 推翻条件

- 活动需要取消、延期、报名截止或人工策展排序时，以新 ADR 扩展显式状态模型。
- 代码审核式目录成为运营瓶颈时，单独评估 D1 活动 CMS、权限、草稿、审核与媒体上传，不在本时间线组件中加入后台例外。
