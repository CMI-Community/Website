# ADR 0005：三屏首页与版本化公共照片目录

- 状态：Accepted
- 日期：2026-08-10
- 关联 Issue：[Website#13](https://github.com/CMI-Community/Website/issues/13)
- Supersedes：无

## 上下文

- `VERIFIED`：根路径当前以 308 暂时跳转到 `/archive/posters`，没有正式官网首页。
- `VERIFIED`：现有 Event Museum 已是可嵌入的模块，并从版本化 R2 公共目录读取 180 张海报。
- `VERIFIED`：首批 Photo Museum 范围为 27 张用户指定的社区现场照片，其中 25 张横向、2 张纵向。
- `ASSUMED`：这 27 张照片已由内容负责人选择为本次公开展示范围；公开目录不记录授权材料、人物身份、原始路径或推断性活动信息。

根路径、公共媒体目录和外部社区入口会长期影响公开 URL、资产边界与回滚方式，因此使用 T3 留痕。

## 决策驱动因素

- 新访客应先理解 CMI Community，再进入照片与活动档案。
- 照片必须保持原始比例、清晰可看，同时避免把原片和本机工作路径带入公开仓库。
- 现有 `/archive/posters` 深链、海报数据和反馈能力必须保持兼容。
- 首页任一媒体目录失败时，社区介绍和另一个 Museum 仍应可用。

## 备选方案

### 根路径三屏首页 + 版本化 R2 照片目录

- 优点：复用现有平台和海报组件；原片不进仓库；目录与资产可独立缓存和回滚。
- 代价：发布时必须同步验证 Worker 与 R2 目录，首页需要处理两个独立数据源的失败状态。

### 把照片直接提交到 `public/`

- 优点：本地开发简单，不依赖 R2 目录。
- 代价：公开仓库体积、品牌内容授权边界和后续版本管理都更难控制。

### 保持现状

- 优点：没有根路由迁移风险。
- 代价：官网继续以海报模块代替社区首页，无法呈现社区定位和照片记忆。

## 决策

1. `/` 改为三个全屏区域组成的正式首页：Community Hero、Photo Museum、Event Museum；`/archive/posters` 继续作为独立完整档案页。
2. Photo Museum 使用 `photo-museum/v1/catalog.json` 和同版本 R2 WebP 资产；浏览器通过同域只读 `/media/photo-museum/v1/...` 投影访问当前环境绑定的 R2。公共记录只允许 `id`、两档图片路径、固有尺寸、客观 alt 与展示顺序。
3. 原始 HEIC/JPEG、哈希、授权材料、本机路径和人物身份不进入公开仓库或公共目录。
4. 首页服务端并行读取照片与海报目录，分别返回可用/不可用状态，不让局部故障覆盖首屏。
5. Discord 是首要社区行动入口；Bilibili 与既有公众号、小红书、Reddit、GitHub、微信入口共用一份公开配置。

## 后果

- 正面：官网形成清晰入口；照片和海报能独立演进；原始素材、代码许可和 CMI 品牌内容继续分离。
- 负面：staging 与 production 发布都增加一组 R2 目录/对象核验；Photo Museum v1 的内容变更需要新目录版本或明确覆盖策略。

## 迁移与回滚

- 先把 `photo-museum/v1` 上传 staging R2，再部署 Worker 并完成桌面、390px、目录失败与 reduced-motion 验证。
- production 只能在 staging 用户验收和人工批准后发布。
- 回滚时恢复根路径到 `/archive/posters` 的 308 行为；R2 v1 资产作为可恢复证据保留，不在回滚时删除。

## 推翻条件

- Photo Museum 进入后台内容发布流程并需要草稿、审核、修订或细粒度权限时，新 ADR 评估迁移到 D1/media_assets 发布模型。
- R2 公共目录无法满足可访问性、缓存或资产撤回要求时，新 ADR 评估媒体服务接口，不直接改写本记录。
